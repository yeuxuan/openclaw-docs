# Session Compaction

会话太长时，OpenClaw 需要压缩上下文，保留重点，丢掉不需要留意的细节。

目标不是忘记一切，而是让模型还能在上下文窗口里继续工作。

继续阅读：[上下文压缩](/tutorials/concepts/compaction)。

## 为什么需要压缩

模型一次只能看有限上下文。会话越来越长时，如果不整理，后面的消息可能挤不进去。

压缩会把“有用事实、当前目标、已经做过的事”留下，把重复寒暄、无关输出和过长日志丢掉或概括。

## 新手提醒

压缩不是备份。需要留意文件和长期知识应该放进工作区、Wiki 或记忆系统，不要只依赖聊天上下文。

## 超时与恢复边界

内置压缩的 `agents.defaults.compaction.timeoutSeconds` 默认 180 秒，按每次串行模型请求重新计时，因此多阶段压缩可能超过三分钟；插件自有压缩仍按整个操作限制。

停止运行会停止后续恢复、维护与重试，但不会回滚已经提交的压缩。记忆刷新失败不等于会话被清空，必要压缩失败会保留原对话并报错。

提供商 compact checkpoint 缺少完整重放窗口时，按提示运行 `/compact` 从保存的历史重建；不要通过删除 transcript 来绕过。完整窗口上限 16 MiB，预算超限走正常客户端压缩而非截断 checkpoint。
